# معالجة المسارات الاستثنائية — التصميم والإثبات

الاختبار: `tests/failure_paths.py` → النتيجة **20/20 ناجح** (تقرير: `tests/failure_paths_report.json`).

## آلية المعالجة (في `app/util.py`)
كل هاندلر مُغلّف بـ `@trace`، وأي استثناء يُترجم إلى رسالة عربية دون تعطّل:
| نوع الخطأ | الحالة المسجّلة | الرسالة للمستخدم |
|---|---|---|
| فشل واجهة خارجية (`ExternalError`) | `external_error` | «⚠️ تعذّر الاتصال بالخدمة (اسم الخدمة) حاليًا. تأكد من الإنترنت وحاول مرة أخرى بعد قليل.» |
| مدخل غير صالح (`ValueError`) | `bad_input` | «⚠️ مدخل غير صحيح: …» مع تلميح الصيغة |
| أي خطأ آخر | `error` | «⚠️ حدث خطأ غير متوقع. تم تسجيل المشكلة، حاول مرة أخرى.» |

كل حالة تُكتب في جدول `requests` (بـ `req_id`) وجدول `errors` — أي أن الأخطاء **قابلة للتتبع** لا صامتة.

## سيناريوهات الإثبات الفعلي

### 1) فشل شبكة حقيقي (عنوان غير قابل للوصول `http://10.255.255.1:9`)
- النتيجة: `ExternalError: انتهت مدة الاتصال` خلال **4.0s** (لا تعليق)، والرسالة العربية تحمل اسم الخدمة.
- الدليل: ✅ «فشل الشبكة ⇒ رسالة عربية واضحة» + «لا تعليق».

### 2) مدخلات غير صالحة عبر الهاندلرات الفعلية
| المدخل | الرسالة الواقعة |
|---|---|
| `/ayah abc` | «⚠️ مدخل غير صحيح: الصيغة يجب أن تكون سورة:آية (مثال: 2:255)» |
| `/ayah 999:1` | «… رقم السورة يجب أن يكون بين 1 و 114» |
| `/ayah 2:0` | «… رقم الآية غير منطقي (1-286)» |
| `/tafsir ::` | «… استخدم أرقامًا فقط بصيغة سورة:آية» |
| `/hz x` | «… الصيغة يجب أن تكون سورة:آية» |
| `/tasmia 5` | «… الصيغة يجب أن تكون سورة:آية» |
| `/surah 999` | «⚠️ رقم السورة غير صحيح (1-114).» |

### 3) ضغط مدخلات (40 طلبًا متزامنًا)
- 40/40 ردّت، **0 استثناءات غير مُدارة** ⇒ لا تعطّل تحت الضغط.

### 3b) تحديث بلا مستخدم (منشور قناة / أدمن مجهول)
- ظهر هذا الخطأ **فعليًا على البوت الحقيقي** (`AttributeError: 'NoneType' object has no attribute 'id'` في `text_router`) عند وصول تحديث بلا `effective_user`.
- الإصلاح: فرض تجاهل هادئ في `@trace` لأي تحديث بلا مستخدم (مع تسجيل الحالة `ignored`) بدل الانهيار.
- الإثبات: ✅ «نص حر بلا مستخدم ⇒ تجاهل بلا انهيار» و«/start بلا مستخدم لا ينهار الجلسة».

### 4) تدهور لطيف (Graceful degradation)
- **فشل ffmpeg** ⇒ البوت أرسل **صورة + صوت** بدل الفيديو (المخرجات المُلتقطة: `{photo, audio}`) بلا انهيار/تعليق.
- **صوت السورة غير متاح** ⇒ تراجع تلقائي لـ **صوت الآية الأولى**: «🎧 سورة الإخلاص — تلاوة الآية الأولى (ماهر المعيقلي)».

### 5) توكن غير صالح
- تشغيل `python -m app.main --check` بتوكن سيئ ⇒ **exit code = 1** ورسالة واضحة، دون انهيار.

### 6) التتبّع بعد حالات الفشل
- التخزين الفعلي: `requests=169`, `errors=19`, `users=2`, `khatma=9`, `hifz=1`.
- توزيع حالات آخر الطلبات: `{'ok': 93, 'bad_input': 6, 'error': 6}` ⇒ الأخطاء المُدارة مُسجَّلة فعليًا.
- **السجل لا يحتوي التوكن** (تحقق آلي) ⇒ لا تسريب في `logs/bot.log`.

## الخلاصة
كل حالة فشل مُختبرة تُنتج: رسالة عربية واضحة + تسجيلًا قابلًا للتتبع + بقاء البوت شغّالًا. لا مسارات صامتة ولا تعليق.
